# spec.md — UC-10 «Подати скаргу на гравця» (машина станів)

## 1. Процес і UC
**UC-10 Подати скаргу на гравця.** Мета: Player A скаржиться на Player B; `reports_count` B зростає, а при ≥ 5 B отримує `flagged` і зникає з видачі.
Пов'язано: **US-05** (SC-040…045, SC-055), US-08 (SC-055); **REP-01, REP-02, REP-03**; **ADM-04** (лише через SC-055, див. §9); UC-14.

## 2. Учасники
- **Player A** — скаржник (ініціює).
- **Система** (ReportService) — перевіряє, зберігає, веде лічильник.
- **Player B** — відповідач, об'єкт скарги (пасивний). Пара «A — B» зберігається у зв'язку «скаржиться на».
Зовнішніх систем у вхідних даних немає.

## 3. Передумови й постумови
- **Передумови:** A авторизований; B існує (SC-040, SC-055).
- **Успіх:** пара «A — B» збережена; `reports_count` B +1; якщо ≥ 5 — `verification_status` B = `flagged` незалежно від попереднього (SC-044, 045).
- **Відхилення / збій:** дані не змінено (SC-042, 043, 041).

## 5. Таблиця станів
| Стан | Що означає | Вхід | Вихід | Умова переходу |
|---|---|---|---|---|
| Запит отримано | A подав скаргу на B | submitReport | → розгалуження c1 | завжди |
| Скаргу відхилено | дані без змін | c1 або c2 | кінець | A = B або пара є |
| Транзакція відкрита | неподільна операція (REP-01) | c2 | → Прийнято / Скасовано | пари немає |
| Пару збережено / Лічильник збільшено | дві гілки операції | fork | join | savePair ok / increment ok |
| B позначено flagged | REP-03 спрацював | c3 | join транзакції | `reports_count` ≥ 5 |
| Скаргу прийнято | зміни зафіксовано | Tx | кінець | commit |
| Скаргу скасовано | жодна зміна не застосована | Tx | кінець | збій гілки → rollback |

## 6. Розгалуження
| Умова | Результат | SC | Вимога |
|---|---|---|---|
| A = B | відхилено, без existsPair | SC-043 | REP-02 |
| A ≠ B, пара вже є | відхилено | SC-042 | REP-02 |
| A ≠ B, пари немає | транзакція | SC-040 | REP-01 |
| після join: `reports_count` ≥ 5 | `flagged` у тій самій операції | SC-044, 045, 055 | REP-03 |
| після join: `reports_count` < 5 | статус не змінюється | SC-040 | REP-03 |
Перші три умови взаємовиключні й вичерпні (перевірка у порядку «себе → дубль»); останні дві — так само.

## 7. Паралельні гілки (fork/join)
Гілки: **savePair(A,B)** і **incrementReportsCount(B)**; join — перед перевіркою `≥ 5`. Це **моделювальне рішення**: показати, що обидві зміни належать одній неподільній операції (REP-01). У sequence вони йдуть послідовно всередині однієї транзакції; фактичної паралельності вимоги не задають.
Збій однієї гілки (SC-041): `rollback()`, обидві зміни скасовано, пару не збережено, `reports_count` без змін.

## 8. Таблиця повідомлень
| Повідомлення | Від → до | При відповіді | Без відповіді / збій |
|---|---|---|---|
| submitReport(reportedPlayerId) | Player A → Система | старт перевірок | не визначено у вхідних даних |
| existsPair(A,B) | Система → зв'язок «скаржиться на» | true → відхилити; false → транзакція | не визначено |
| savePair(A,B) | Система → зв'язок | ok → join | збій → rollback, reportFailed (SC-041) |
| incrementReportsCount(B) | Система → Player B | нове `reports_count` → перевірка ≥ 5 | збій → rollback (SC-041) |
| setVerificationStatus(B, flagged) | Система → Player B | ok → commit | не змодельовано |
| reportAccepted | Система → Player A | кінець, успіх | — |
| reportRejected (причина: самоскарга SC-043 / дубль SC-042) | Система → Player A | кінець, «показується помилка» | — |
| reportFailed | Система → Player A | кінець, нічого не застосовано | — |
Назви взято з sequence-040…045, 055; isSelfReport, beginTransaction, commit, rollback — службові кроки Системи.

## 9. Чому машина станів
Процес — це стани скарги й даних B з гардами та атомарною операцією; стан «flagged» і лічильник природно моделюються станами. Activity дала б потік дій без явних станів даних, BPMN надлишковий для одного UC з одним внутрішнім сервісом. **Mermaid не підтримує swimlanes**, тому ролі позначено префіксами «Player:» / «Система:» у мітках переходів.

## 10. Обмеження
Не входять: скидання `reports_count` і повернення зі `flagged` (UC-14, SC-050, 051); після повернення нова скарга знову дає `flagged` (SC-055 ✱, ADR-0008 Proposed); вплив `flagged` на видачу (RES-01); скарги неавторизованих.
