# Промпт №2: генерація синтаксису компонентної діаграми Mermaid

**Модель:** Claude Sonnet 5.5 (Anthropic)

---

## 1. Повний текст промпту

До промпту додано файл: `spec.md` (специфікація архітектури Umasearch: модулі та шари, межа системи, provided/required інтерфейси, залежності між компонентами).

```text
На основі файлу spec.md згенеруй синтаксис компонентної діаграми у форматі Mermaid (Component Diagram).

Вимоги до діаграми:
1. Чітко відокремся межами системи (наприклад, за допомогою subgraph для внутрішніх компонентів системи).
2. Покажи архітектурні шари: UI, Backend API, Service Layer, Data Access, Database.
3. Додай зовнішні системи якщо це необхідно або вказано у вхідних даних (наприклад, клієнтський браузер/додаток, сторонні платіжні або поштові сервіси) зовні меж системи.
4. Використовуй коректні зв'язки з урахуванням provided та required інтерфейсів (або чітких залежностей між компонентами).
5. Назви компонентів і зв'язків мають повністю відповідати сутностям та сервісам, описаним у попередніх лабах.

```

---

## 2. Що видав ШІ

- Файл `component-diagram.mmd`.
- Діаграма містить:
  - зовнішні сутності поза межею системи: Guest, Player, Admin (успадковує Player, ADR-0007) та Браузер;
  - `subgraph SYS` («Система Umasearch») з п'ятьма вкладеними шарами: UI, API / Backend, Сервіси, Data Access, База даних;
  - усі компоненти з `spec.md`: 6 UI-компонентів, `AuthMiddleware`, `RoleGuard`, 5 контролерів, 6 сервісів, 5 репозиторіїв і `TransactionManager`, `Database` з переліком таблиць;
  - зв'язки з підписами інтерфейсів (`IAuthService`, `ISearchService`, `IRentalService`, `IReportService`, `IReferenceDataService`, `IModerationService`, `IPlayerRepository`, `IReportRepository`, `ISharedUmaRepository`, `ISharedCardRepository`, `IReferenceRepository`, `ITransactionManager`, `IDatabase`), provided-інтерфейси `ISession` та `IRoleGuard` показано пунктирними стрілками, required-залежності суцільними;
  - HTTP-ендпоінти на зв'язках `AuthMiddleware` / `RoleGuard` → контролери.

## 3. Розбіжності між промптом і тим, що видав ШІ

| №   | Вимога промпту | Що зроблено | Суть розбіжності |
| --- | -------------- | ----------- | ---------------- |
| 1   | «Додай зовнішні системи, … наприклад, … сторонні платіжні або поштові сервіси» | Платіжних, поштових, OAuth та External API на діаграмі немає; зовні межі лише актори й браузер | Розбіжність лише формальна: `spec.md` (розділи 1–2) прямо фіксує відсутність зовнішніх інтеграцій, тому за умовою «якщо це необхідно або вказано у вхідних даних» їх не додано. ШІ зазначив це у примітках до діаграми |
| 2   | Використати «provided та required інтерфейси» | Інтерфейси подано підписами на стрілках у `flowchart`, а не нотацією UML «lollipop/socket» | Mermaid не має нативного синтаксису компонентної діаграми UML, тому provided/required передано через стрілки та підписи (суцільна стрілка = required, пунктирна = provided для `ISession` і `IRoleGuard`). Для решти provided-інтерфейсів (наприклад, `register`, `authenticate`) окремих вузлів немає, вони вказані лише в підписах |
| 3   | «Чіткі залежності», залежності лише донизу (spec.md, розділ 4) | `AuthMiddleware` → `AuthService` та пунктирні зв'язки `ISession` ідуть у межах шару API, а `UI` підключено лише до `AuthMiddleware` | Зв'язок `UI → AuthMiddleware/RoleGuard → Контролери` у діаграмі спрощено: від UI показано одну стрілку до `AuthMiddleware`, окремі UI-компоненти (`AuthPages`, `SearchPage` тощо) між собою та з API не з'єднані, а лише згруповані в `subgraph` |
