# Додаткова специфікація 03: роль, довідник Rank і статуси ADR

**Дата створення**: 2026-10-05

**Статус**: Прийнято (крім ролі: див. ADR-0005, статус Proposed)

**Розбіжність**: Помилка 3 в `ai/audit.md` («модель не відображає вимог spec; ADR спираються на дані, яких немає в моделі»)

**Промпт**: `ai/04-prompt.md` (spec і діаграма), `ai/05-prompt.md` (ADR)

**Доповнює**: `spec.md` (розділи 2, 3, 4, 6), `erDiagram.mmd`, `adr/0003-rank-as-reference-entity.md`, `adr/0005-role-as-player-attribute.md`

---

## 1. Проблема

1. Роль користувача: ADR-0003 (стара версія) читав роль «з БД», а `spec.md` поля ролі не мав.
2. Правила скарг (один раз на гравця) вимагали зберігати, хто на кого скаржився, а в `spec.md` цього не було (припущення 3).
3. `SharedUma.rank` мав бути значенням із довідника (BR-011, FR-034 старої версії), але довідника в моделі не було; поле було `string` із «літерою й числом».
4. ADR мали статус «Прийнято» при відкритих припущеннях spec.
5. Старі ADR-0001…0003 (PostgreSQL, SQL-пошук, сесії) вибирають стек, а лабораторна №1 стосується тільки ER-моделі.

## 2. Зміни

| Артефакт | Було | Стало |
| --- | --- | --- |
| `spec.md`, Player | поля ролі немає | `role` ∈ {`player`, `admin`}; Guest не зберігається |
| `spec.md`, скарги | сутності немає (припущення 3) | самозв'язок Player N:M Player (див. spec-add-01), AC-12 |
| `spec.md`, Rank | `SharedUma.rank` типу string | сутність `Rank(id, code UK)`; `SharedUma.rank_id` FK |
| `erDiagram.mmd` | роль є, Rank і скарг немає | Rank, зв'язок Rank–SharedUma, самозв'язок скарг |
| ADR | 4 ADR про стек, усі «Прийнято» | 5 ADR про моделювання; ADR-0005 `Proposed`, решта `Accepted` |

## 3. Нові правила

- Нова умка зберігає `rank_id`, що існує в `Rank`; значення `Rank.code` унікальне.
- Admin керує довідником Rank так само, як іншими довідниками.
- Скарга: пара (скаржник, відповідач) унікальна; скаржник ≠ відповідач; `reports_count` збільшується на 1 при кожній новій скарзі.

## 4. Критерії приймання

- Кожна сутність і поле з `erDiagram.mmd` описані в `spec.md` і навпаки.
- Жоден ADR зі статусом `Accepted` не спирається на припущення, позначене як відкрите.
