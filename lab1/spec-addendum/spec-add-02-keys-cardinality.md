# Додаткова специфікація 02: ключі, кардинальності та підписи зв'язків

**Дата створення**: 2026-10-05

**Статус**: Прийнято

**Розбіжність**: Помилка 2 в `ai/audit.md` («діаграма без UK, з однаковими лініями й кардинальністю 1:N замість 1 : 0..1»)

**Промпт**: `ai/04-prompt.md`

**Доповнює**: `spec.md` (розділи 2, 3, 5), `erDiagram.mmd`, `adr/0004-rental-limit-as-cardinality.md`

---

## 1. Проблема

1. Поля, унікальні за spec (`Player.email`, `Player.trainer_id`), у діаграмі не мали `UK`.
2. Усі зв'язки були записані лінією `--`, хоча FK не входить у PK дочірньої сутності.
3. Правило «один Player виставляє 1 SharedUma і 1 SharedCard» було записане як 1:N з приміткою; кардинальність моделі суперечила правилу.
4. Підписи зв'язків були англійськими, тоді як зв'язки в spec описані українською.

## 2. Зміни

| Артефакт            | Було                                                          | Стало                                                           |
| ------------------- | ------------------------------------------------------------- | --------------------------------------------------------------- |
| `spec.md`, розділ 3 | Player → SharedUma / SharedCard: 1:N + примітка про ліміт     | 1 : 0..1                                                        |
| `spec.md`, розділ 2 | `SharedUma.player_id`, `SharedCard.player_id`: лише FK        | FK і UK (щоб ліміт 1 + 1 діяв на рівні моделі)                  |
| `erDiagram.mmd`     | `uuid email`, `uuid trainer_id` без UK; `--` на всіх зв'язках | `email UK`, `trainer_id UK`; `..` для неідентифікуючих зв'язків |
| `erDiagram.mmd`     | `Player                                                       |                                                                 | --o{ SharedUma` | `Player |     | ..o | SharedUma` (так само для SharedCard) |
| `erDiagram.mmd`     | підписи `"has"`, `"is used in"`                               | підписи українською: «має», «використовується в»                |

## 3. Нові критерії

- **AC-04** (у `spec.md`): кожен UK зі spec позначений у діаграмі; кожен FK має зв'язок.
- **AC-05** (у `spec.md`): ліміт «1 + 1» виражений як кардинальність 1 : 0..1.

## 4. Критерії приймання

- Спроба створити другу SharedUma або другу SharedCard для того самого Player порушує унікальність `player_id`.
- Лінія `--` у діаграмі не використовується там, де FK не входить у PK; у поточній моделі всі FK неідентифікуючі.
