# Промпт №5: перегенерація набору ADR для лабораторної №1

**Модель:** Claude Sonnet 5.5 (Anthropic)

---

## 1. Повний текст промпту

````text
На основі нового spec.md, erDiagram.mmd, specadd/ та шаблону adr/adr-template.md створи набір ADR. Відповідай українською; заголовки та метадані ADR залиш англійськими, як у шаблоні.

Правила
- ADR мають бути про рішення моделювання (зв'язки, кардинальності, довідники, ролі), а не про стек, СУБД чи сесії.
- Структуру й заголовки шаблону не змінюй, нових розділів і полів метаданих не додавай.
- Кожен ADR — одне рішення, щонайменше 2–3 варіанти з плюсами й мінусами, посилання на AC-xx зі spec.md та на addendum.
- Статус `Accepted` став лише тоді, коли ADR не спирається на відкриті припущення spec.md. Якщо рішення залежить від непідтвердженого припущення, статус `Proposed` і позначка [NEEDS CLARIFICATION: що саме].
- Не вигадуй вимог і чисел поза spec.md.
- Імена файлів: NNNN-короткий-заголовок-латиницею.md, нумерація з 0001.
- Перед завершенням перевір, що всі AC-xx з посилань існують у spec.md.
````

## 2. Що видав ШІ

П'ять ADR у `adr/`:

| №    | Рішення                                           | Статус   |
| ---- | ------------------------------------------------- | -------- |
| 0001 | Зв'язок N:M SharedUma ↔ Factor без сполучної таблиці | Accepted |
| 0002 | Скарги як самозв'язок Player N:M Player            | Accepted |
| 0003 | Rank як довідникова сутність                       | Accepted |
| 0004 | Ліміт «1 + 1» як кардинальність 1 : 0..1           | Accepted |
| 0005 | Роль як атрибут Player                             | Proposed |

Старі ADR-0001…0003 (PostgreSQL, SQL-пошук, сесії) і ADR-0004 про таблицю Report замінено. Їх варто залишити в історії git або перенести в `ai/archive/` як слід першої генерації.

## 3. Розбіжності між промптом і результатом

| №   | Вимога промпту | Що зроблено | Суть розбіжності |
| --- | -------------- | ----------- | ---------------- |
| 1   | Статус `Accepted` лише без відкритих припущень | ADR-0003 `Accepted`, хоча повний список кодів rank у spec не підтверджено | Список кодів винесено у Follow-up actions; відкрите питання лишилося не в Context, а в наступних діях |
| 2   | Шаблон без змін | Прибрано зайвий рядок `Supersedes`, доданий під час першої спроби | Виправлено до завершення; у фінальних файлах метадані збігаються з шаблоном |
| 3   | Кожен ADR — одне рішення | ADR-0002 разом із рішенням «Report як зв'язок» фіксує, що `reports_count` лишається полем | Друге твердження взяте з вхідних даних (поле Player), але формально сусідить із основним рішенням |
| 4   | Кожен ADR — щонайменше 2–3 варіанти | Усі п'ять мають по три варіанти | Розбіжності немає; частина альтернатив (Option 3 в ADR-0004, 0005) штучна й слабша за вибраний варіант |
| 5   | Перевірити існування AC-xx | Перевірка виконана скриптом: усі посилання існують | Розбіжності немає; змістову узгодженість ADR зі spec перевірено вручну |
