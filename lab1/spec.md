# Специфікація ER-моделі: Umasearch

**Дата**: 2026-10-05 · **Статус**: Чернетка · **Доповнення**: `spec-addendum/spec-add-01…03`

## 1. Намір

> В грі відсутня зручна система пошуку гравців у яких можна позичити умок та сапорт картки для кар'єри, які є обов'язковими у грі, через що гравці використовують різні сторонні джерела для пошуку потрібних їм гравців. Цей проєкт буде спрощувати пошук усім гравцям які намагаються досягти кращих результатів у грі.

Umasearch — вебсайт для гравців Umamusume: Pretty Derby. Користувач вибирає параметри умки або картки, запит іде до БД, підходящі варіанти повертаються і виводяться на екран. Гравець також може виставити власну умку та картку в рентал.

## 2. Сутності та атрибути

Типи: `uuid`, `string`, `int`, `datetime`. Усі поля обов'язкові.

| Сутність    | Вид      | Атрибути (обмеження)                                                                                                                                                                                                                                                                                     |
| ----------- | -------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Player      | дані     | `id` PK; `email` UK (валідний формат); `password` (8–16 символів, лише хеш); `trainer_id` UK (рівно 9 цифр); `trainer_name` (1–30); `verification_status` (`unverified` за замовчуванням, `verified`, `flagged`); `reports_count` (≥ 0, за замовчуванням 0); `role` (`player` за замовчуванням, `admin`) |
| Umamusume   | довідник | `id` PK; `name`; `icon`                                                                                                                                                                                                                                                                                  |
| SupportCard | довідник | `id` PK; `name`; `icon`; `card_type` (Speed, Stamina, Power, Guts, Wit, Friend); `rarity` (R, SR, SSR)                                                                                                                                                                                                   |
| Factor      | довідник | `id` PK; `name` UK; `star_rate` (1–9); `category` (Blue, Red, Green, White)                                                                                                                                                                                                                              |
| Rank        | довідник | `id` PK; `code` UK (наприклад, "UE3", "UG5"; атомарний код)                                                                                                                                                                                                                                              |
| SharedUma   | дані     | `id` PK; `player_id` FK UK; `umamusume_id` FK; `rank_id` FK; `speed_stat`, `stamina_stat`, `power_stat`, `guts_stat`, `wit_stat` (0–2000); `created_at`; `updated_at`                                                                                                                                    |
| SharedCard  | дані     | `id` PK; `player_id` FK UK; `support_card_id` FK; `level` (1–50); `limit_break` (0–4); `created_at`; `updated_at`                                                                                                                                                                                        |

## 3. Зв'язки

| A           | B          | Кардинальність | Через                        | Примітка                                             |
| ----------- | ---------- | -------------- | ---------------------------- | ---------------------------------------------------- |
| Player      | SharedUma  | 1 : 0..1       | `SharedUma.player_id`        | ліміт «1 умка на Player»                             |
| Player      | SharedCard | 1 : 0..1       | `SharedCard.player_id`       | ліміт «1 картка на Player»                           |
| Umamusume   | SharedUma  | 1 : N          | `SharedUma.umamusume_id`     |                                                      |
| SupportCard | SharedCard | 1 : N          | `SharedCard.support_card_id` |                                                      |
| Rank        | SharedUma  | 1 : N          | `SharedUma.rank_id`          | значення rank лише з довідника                       |
| SharedUma   | Factor     | N : M          | —                            | власних атрибутів немає, тому без сполучної таблиці  |
| Player      | Player     | N : M          | —                            | «скаржиться на»; власних атрибутів немає; не на себе |

## 4. Ролі

- **Guest** — не зберігається; шукає, `trainer_id` не бачить.
- **Player** (`role = player`) — шукає, бачить `trainer_id`, керує своїми SharedUma/SharedCard, скаржиться.
- **Admin** (`role = admin`) — наповнює довідники (Umamusume, SupportCard, Factor, Rank), верифікує `trainer_id` за скриншотом, переглядає скарги, повертає гравців зі `flagged`.

## 5. Критерії прийняття

**Модель**

- **AC-01** Усі `id` мають тип `uuid`; кожен FK має той самий тип, що й PK, на який посилається.
- **AC-02** Сполучних таблиць немає: чистий N:M — це зв'язок між сутностями; асоціативна сутність допустима лише тоді, коли зв'язок має власні атрибути.
- **AC-03** Модель у 3NF: атрибути атомарні, значення rank беруться лише з довідника Rank, `Factor.name` унікальний. Єдине свідоме похідне поле — `Player.reports_count` (дорівнює кількості скарг на гравця).
- **AC-04** Назви сутностей і полів у діаграмі збігаються зі spec; кожен UK зі spec позначений; кожен FK має зв'язок.
- **AC-05** Кардинальності відповідають розділу 3; ліміт «1 + 1» виражений як 1 : 0..1.
- **AC-06** До моделі додано ER-рендер, який збігається з описом.

**Дані**

- **AC-07** Спроба порушити обмеження розділу 2 (дублікат email/trainer_id, trainer_id не з 9 цифр, пароль поза 8–16, стат поза 0–2000, level поза 1–50, limit_break поза 0–4, rank поза довідником) відхиляється.
- **AC-08** Новий Player отримує `unverified`, `reports_count = 0`, `role = player`. Вхід лише за email + password; відновлення пароля немає.
- **AC-09** Рентал активний, доки власник сам його не зніме; Player може повністю змінити свої умку і картку; `created_at` / `updated_at` ведуться автоматично.

**Поведінка**

- **AC-10** Фільтри умки: Umamusume (мульти-вибір), мінімум кожного з 5 статів, rank, Factor (мульти-вибір, усі вибрані одночасно). Фільтри картки: SupportCard (мульти-вибір), card_type, rarity, мінімальні level і limit_break. Фільтри між собою поєднуються через AND; мульти-вибір — збіг з будь-яким вибраним.
- **AC-11** У видачі: без `flagged`; спочатку verified, потім за `created_at` спадаючи; по 20 на сторінку; `trainer_id` лише авторизованим; порожній результат — «Нічого не знайдено» і пропозиція послабити фільтри.
- **AC-12** Скарга: від одного гравця на іншого один раз; на себе заборонена; кожна нова скарга збільшує `reports_count` на 1; при `reports_count ≥ 5` статус стає `flagged` автоматично, в одній операції зі збереженням скарги.

## 6. Припущення (додумано)

1. Admin = модератор. Після розгляду `flagged` Admin обирає `unverified` або `verified` і може скинути `reports_count` (у вхідних даних не вказано).
2. Роль зберігається атрибутом `Player.role` (ADR-0005, статус Proposed).
3. Тип `datetime` для `created_at` / `updated_at`.
4. Правила видалення записів (крім зняття рентала власником) не визначені.
5. Показники «3 дії» та «2 секунди для 95% запитів» із чернетки прибрано: у вхідних даних їх немає.
