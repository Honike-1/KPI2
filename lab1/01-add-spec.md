# Додаткова специфікація 02: сутність Report для скарг

**Дата створення**: 2026-10-05

**Статус**: Чернетка

**Розбіжність**: Помилка 2 в `audit.md` («ADR-0004 вводить сутність Report поза моделлю, а ADR мають статус «Прийнято» попри відкриті припущення»)

**Промпт**: `03-prompt.md`

**Доповнює**: `spec.md` (розділи 5, 6, 8, 12), `erDiagram.mmd`, `0004-reports-and-flagging.md`

---

## 1. Проблема

FR-028 і SC-010 вимагають, щоб один користувач не міг поскаржитися на одного гравця двічі, але в `spec.md` немає сутності для зберігання того, хто на кого поскаржився (розділ 12, п. 3). ADR-0004 вводить таку сутність, не змінивши `spec.md` і `erDiagram.mmd`, і має статус «Прийнято».

## 2. Сутність

### 5.8. Report

**Опис**: скарга одного Player на іншого. Динамічні дані.

| Поле        | Тип  | Ключ (PK/FK)   | Обов'язкове | Обмеження / допустимі значення                 | Опис                         |
| ----------- | ---- | -------------- | ----------- | ---------------------------------------------- | ---------------------------- |
| reporter_id | uuid | FK → Player.id | Так         | Має існувати в Player                          | Гравець, який подає скаргу   |
| reported_id | uuid | FK → Player.id | Так         | Має існувати в Player; не дорівнює reporter_id | Гравець, на якого скаржаться |

Складений унікальний ключ: (reporter_id, reported_id). Інших полів немає (ADR-0004 їх не вводить).

## 3. Зв'язки

| Сутність A | Сутність B | Тип зв'язку | Через яке поле     | Опис                                           |
| ---------- | ---------- | ----------- | ------------------ | ---------------------------------------------- |
| Player     | Report     | 1:N         | Report.reporter_id | Один Player може подати багато скарг           |
| Player     | Report     | 1:N         | Report.reported_id | На одного Player може бути подано багато скарг |

## 4. Нові правила та вимоги

- **BR-021**: пара (reporter_id, reported_id) унікальна (джерело: FR-028, SC-010).
- **BR-022**: reporter_id не дорівнює reported_id (джерело: припущення 12 у `spec.md`).
- **FR-036**: при поданні скарги Система МАЄ в одній операції додати запис Report, збільшити `Player.reports_count` гравця reported_id на 1 і встановити `verification_status` = `flagged`, якщо `reports_count` ≥ 5 (уточнює FR-027, FR-029).
- **FR-037**: Admin МАЄ мати змогу переглядати записи Report (уточнює FR-035).

Додається до `erDiagram.mmd`:

```text
Report {
    uuid reporter_id FK
    uuid reported_id FK
}

Player ||..o{ Report : "reports"
Player ||..o{ Report : "is reported in"
```

## 6. Критерії приймання

- Повторна скарга від того самого користувача на того самого гравця відхиляється (SC-010).
- Скарга гравця на себе відхиляється (BR-022).
- Гравець із `reports_count` ≥ 5 отримує `flagged` разом із записом скарги в одній операції (SC-009).
