# Промпт №2: генерація EARS-вимог

**Модель:** Claude Sonnet 5.5 (Anthropic)

---

## 1. Повний текст промпту

Вхід: `spec.md` (ER-модель), `spec.md` (актори й цілі), `spec-add-01…03`, `erDiagram.mmd`, ADR-0001…0005.

```
Ти допомагаєш виконати лабораторну для проєкту Umasearch. Надаю тобі специфікацію проєкту, специфікацію акторів, додаткові специфікації, ER-модель, ADR-файли.Нічого не вигадуй і не змінюй.

Ти повинен створити EARS-вимоги (WHEN <тригер>, система SHALL (<реакція> / WHILE <стан>, …), приклад оформлення вимог знайди сам. Якщо у специфікаціях або ADR не вказані дані що дозволяли б описати сценарій, винеси їх у список розбіжностей.
```

## 2. Що видав ШІ

Один файл `requirements-ears.md` українською.

---

## 3. Розбіжності між промптом та тим, що видав ШІ

| №   | Вимога промпту | Що зроблено | Розбіжність |
| --- | -------------- | ----------- | ----------- |
| 1   | Шаблон: WHEN/WHILE | Використано ще Ubiquitous («Система SHALL…») та IF…THEN | Промпт називає лише WHEN і WHILE; решту взято зі стандарту EARS, бо «приклад оформлення знайди сам» |
| 2   | Нічого не вигадувати | REQ-RENT-04 («припинити показ» при знятті рентала), REQ-RES-03 (поділ за авторизацією) уточнюють наслідок, якого в spec дослівно немає | Наслідок виведено з формулювань «зняти рентал» і «`trainer_id` лише авторизованим» |
| 3   | Створити вимоги з розбіжностей лише там, де даних вистачає | Версія 1 мала по одній вимозі на умову; після скорочення REQ-AUTH-04, REQ-RENT-05 та REQ-REP-02 об'єднують кілька умов в одну | Вимоги стали менш атомарними, а тому менш зручними для тестування |
