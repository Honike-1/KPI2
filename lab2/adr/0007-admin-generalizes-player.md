# ADR-0007: Admin як спеціалізація Player на діаграмі

**Status**: Proposed

**Date**: 2026-10-22

---

## Context

За моделлю даних Player і Admin — один тип запису з різним `Player.role` (ADR-0005, статус `Proposed`). На діаграмі v1 Admin був окремим актором без зв'язку з Player (`audit.md`, п. 3.1). Права Admin на пошук, рентал і скарги у вхідних документах не визначені; наявність `trainer_id` в Admin також відкрита. Крім того, в Admin v1 була асоціація з UC-02 (вхід), що дублює вхід Player.

## Decision Drivers

- Узгодженість діаграми з моделлю даних (Завдання 1).
- Умова лабораторної: діаграма має містити узагальнення.
- Не вигадувати права Admin, яких немає у вхідних документах.

## Considered Options

1. Admin — окремий актор без зв'язку з Player (v1).
2. Admin → Player (узагальнення акторів); Admin додатково пов'язаний з UC-11…UC-14.
3. Admin — окремий актор, але з приміткою «Admin = Player з `role = admin`».

## Decision Outcome

Chosen option: **Option 2**, тому що вона точно відображає модель даних (одна сутність, різна роль) і додає друге узагальнення на діаграмі (разом з UC-03/UC-04 → UC-20). Наслідок: за семантикою UML Admin успадковує всі use case Player; це припущення (✱), доки права Admin не підтверджено.

## Consequences

### Positive

- Діаграма узгоджена з ER (один тип запису).
- Прибрано дублювання асоціації Admin → UC-02.

### Negative and risks

- Admin формально може шукати, виставляти рентал і скаржитися; вхідні документи цього не підтверджують.
- Якщо ADR-0005 буде змінено (окрема сутність Admin), діаграму треба переробити.

### Follow-up actions

- [ ] Після рішення по ADR-0005 підтвердити або скасувати успадкування.
- [ ] Визначити, чи може Admin бути відповідачем скарги (відкрите питання 5 в EARS).

## Pros and Cons of the Options

### Option A

Окремий актор.

- Pros: нічого не успадковує; не вигадує прав.
- Cons: суперечить моделі даних; діаграма вводить в оману.

### Option B

Узагальнення Admin → Player.

- Pros: відповідає ER; друге узагальнення на діаграмі.
- Cons: неявно надає Admin права Player.

### Option C

Окремий актор з приміткою.

- Pros: не вигадує прав; пояснює зв'язок із даними.
- Cons: зв'язок лише текстовий; на діаграмі немає узагальнення між акторами.
